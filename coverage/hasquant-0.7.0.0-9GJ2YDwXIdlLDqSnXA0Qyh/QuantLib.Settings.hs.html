   42 -- |Sets the x87 floating-point unit to 64-bit extended precision.
   43 --
   44 -- Call this once at program start on Windows, before any pricing. By the time Haskell
   45 -- code runs there, the x87 unit sits at 53-bit precision, where a binary linked by
   46 -- clang++ rather than ghc has 64-bit; every 80-bit @long double@ operation inside
   47 -- QuantLib is then silently rounded to double. That matters because @boost::math@ promotes @double@
   48 -- arguments to @long double@ by default, so its distributions lose the precision their
   49 -- algorithms assume -- returning quietly less accurate answers, or failing to converge
   50 -- outright (@hestonSLVFDMModel@ throws out of @quantile(non_central_chi_squared)@
   51 -- without this).
   52 --
   53 -- A no-op on every other platform and on non-x86 Windows. The control word is
   54 -- per-thread, so with a threaded runtime call it on each OS thread that prices. Only
   55 -- the x87 unit is touched: Haskell's own 'Double' arithmetic is SSE\/MXCSR and is
   56 -- unaffected either way.
   57 setExtendedPrecision :: IO ()
   58 setExtendedPrecision =
   59   setExtendedPrecision'_ >>
   60   return ()
